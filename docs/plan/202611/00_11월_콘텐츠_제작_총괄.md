## 2. 편집 방향

이번 달 공통 질문은 “연말과 새해를 앞두고 내 돈이 얼마나 달라지는가?”다. 1번은 행동 체크리스트, 2~4번은 개인별 숫자 계산, 5번은 같은 기준의 기업 비교로 답한다.

- 계산 결과를 먼저 보여주고, 근거·조건·예외를 바로 아래에 제공한다.
- 소득공제액·세액공제액·환급액·보험료 공제 후 금액·세후 실수령액을 구분한다.
- 모든 최신 수치에 적용연도, 적용기간, 확인일, 공식 출처를 기록한다.
- 검색량과 수익 전망은 측정 전에는 수치로 주장하지 않는다.
- 제목의 연도, 화면의 연도, 계산 설정의 연도가 같아야 한다.
- 독자가 이해해야 하는 가정은 제품에 표시하고, 개발 설정·관리 상태 코드는 내부에 둔다.

## 4. 공통 제작 단계

1. 편집: 기존 페이지·검색 성과·중복 URL을 확인하고 최종 제목과 범위를 확정한다.
2. 근거 정리: 공식 자료 원문, 시행일, 단위, 표 위치를 출처 장부에 기록한다.
3. 계산 설계: 입력·출력·수식·반올림·예외를 명세와 예시로 고정한다.
4. 제작: 기존 디자인과 컴포넌트를 사용해 모바일부터 구성한다.
5. 검수: 수치, 문장, 링크, 접근성, 개인정보, SEO를 확인한다.
6. 배포: 사이트맵과 내부 링크를 반영하고 실제 URL에서 대표 시나리오를 확인한다.
7. 측정: 7일·28일 기준으로 검색 유입과 계산 완료·관련 페이지 이동을 확인한다.

## 5. 문서의 상태 표기

- **확인:** 이번 조사에서 공식 공개 자료로 근거를 찾은 내용. 배포 직전 재확인한다.
- **제작 가정:** 범위와 UX를 정하기 위해 채택한 조건. 독자에게 영향을 주면 화면에 설명한다.
- **배포 전 확인:** 이번에 원문·적용요건·최신 개정까지 대조하지 못한 내용. 검증 전 확정값으로 사용하지 않는다.
- **후속:** 이번 배포에 포함하지 않아도 핵심 질문에 답할 수 있는 확장 기능.

출처 장부 공통 필드: source_id, 기관, 문서명, URL, 발표일, 확인일, 적용 시작·종료일, 조문/표/페이지, 원단위, 검증 상태, 연결한 계산 규칙, 검토 메모. 숫자의 상태가 바뀌면 연동된 예시·차트·메타 설명도 함께 바꾼다.

## 6. 공통 UI·개인정보 요구사항

- 입력 라벨은 항상 노출한다. 단위는 원·만원·%·%p를 구분한다.
- 큰 금액은 천 단위 구분과 한글 환산 보조를 제공한다.
- 빈칸과 0을 구분하고, 오류 입력에서는 이전 계산 결과를 현재 결과처럼 남기지 않는다.
- 계산 버튼·프리셋·초기화·상세 근거 펼치기를 키보드로 조작할 수 있어야 한다.
- 360px 화면에서 본문이 가로로 넘치지 않아야 한다. 표는 이름 열 고정 또는 카드형 전환을 사용한다.
- 금액 차이를 색으로만 표현하지 않고 증가·감소 텍스트와 부호를 같이 표시한다.
- 급여·납입액·손익 등 입력값은 기본적으로 브라우저 안에서 처리한다.
- 분석 이벤트에 입력 금액, 결과 금액, 가족 정보, 종목명, 공유 URL을 보내지 않는다.
- 공유는 기본적으로 페이지 링크만 복사한다. 입력값 포함 공유는 후속 기능으로 분리한다.
- 원문 자료 다운로드를 제외한 계산은 로그인 없이 제공하는 것을 기본으로 한다.

## 7. 공통 SEO와 측정

- 신규 슬러그는 제안값이다. 인벤토리와 충돌 여부를 확인한 뒤 생성한다.
- 갱신 페이지는 URL을 유지하고 제목·설명·본문·구조화 데이터·수정일을 일치시킨다.
- 계산기 파라미터가 붙은 주소를 별도 검색 페이지로 노출하지 않는다.
- 리포트는 Article, 계산기는 실제 콘텐츠에 맞는 WebApplication 및 BreadcrumbList 등을 검토한다. 구조화 데이터만으로 검색 확장 노출을 약속하지 않는다.
- FAQ는 본문에 실제 문답을 제공한다. FAQPage는 검색엔진 정책과 사이트 적격성 확인 후 선택한다.
- 모든 페이지에 방법론, 공식 출처, 업데이트 기록, 관련 콘텐츠를 넣는다.

공통 이벤트: page_view, calculator_start, calculator_complete, preset_select, methodology_expand, related_content_click, source_click. 리포트는 checklist_interact와 calculator_cta_click을 추가한다. 이벤트에는 페이지 식별자·기능 구분·규칙 버전 등 비민감 메타데이터만 둔다.

성과는 기존 사이트 기준선과 비교한다. 임의의 검색량·CTR·매출 목표는 만들지 않는다. 신규 페이지는 28일 기준선을 확보하고, 갱신 페이지는 전후 동일 요일·유사 기간과 검색어 구성을 함께 비교한다.

## 8. 역할과 완료 기준

| 역할 | 책임 | 완료 산출물 |
|---|---|---|
| 편집 담당 | 검색 의도, 본문, 예시, 공식 출처 | 최종 원고와 출처 장부 |
| 개발 담당 | 계산, 버전, 접근성, 이벤트 | 기능 구현과 대표 시나리오 결과 |
| 검토 담당 | 세법·요율·회계 기준 대조 | 검토 결과와 미해결 항목 |
| 운영 담당 | 배포, 내부 링크, 지표 확인 | 배포 기록과 7일·28일 점검 |

담당자 이름은 미지정 상태다. 한 사람이 여러 역할을 맡아도 계산 결과와 출처의 대조 단계는 생략하지 않는다.

완료 조건: 핵심 시나리오 정상 작동, 적용기간 표시, 예시 일치, 지원하지 않는 경우 안내, 깨진 링크 없음, 개인정보 이벤트 미전송, 모바일 검수, 실제 배포 후 재계산. 문서에 남은 ‘배포 전 확인’ 항목이 핵심 결과에 영향을 주면 해결하거나 해당 기능을 제외한 뒤 배포한다.
