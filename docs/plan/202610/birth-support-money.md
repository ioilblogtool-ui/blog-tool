## 1. 페이지 목적

“2027년에 아이를 낳으면 정부에서 얼마를 받을 수 있나?”라는 질문에 출생일·출생순위·지역·양육 방식 기준으로 답하는 대표 계산기를 만든다. 새 URL을 만들지 않고 기존 출산지원금 계산기 중 하나를 개선한다.

조사 순서: 프로젝트 문서 → 등록 목록·인벤토리 → 실제 페이지·데이터·스크립트 → 공식 웹 자료. 읽은 문서는 `CLAUDE.md`, `AGENT.md`, `AGENTS.md`, `CONTENT_GUIDE.md`, `docs/REPORT_CONTENT_GUIDE.md`, `docs/ARCHITECTURE.md`, `docs/QUALITY_SCORE.md`, 대조한 목록은 `src/data/tools.ts`, `src/data/reports.ts`, `docs/sheets/page_inventory_2026-10-07.csv`. 기존 기획서 형식은 `docs/plan/202610/welfare-benefit-eligibility-2027-update.md`를 따랐다.

### 1-1. 키워드 검색 결과

`출산지원금 / 부모급여 / 아동수당 / 첫만남이용권 / 육아지원금 / 출산장려금 / 아이맞이지원금 / 아동기본수당`으로 `src/pages`, `src/data`, `public/scripts`를 검색했다.

- 직접 계산 페이지: `birth-support-total`, `birth-support-money`, `baby-government-support`, `single-parental-leave-total`
- 비용·소득 기준 계산 중 지원금을 언급하는 페이지: `pregnancy-birth-cost`, `postnatal-care-income-eligibility`, `parental-leave`, `parental-leave-pay`
- 리포트: `birth-support-by-region-2026`, `newlywed-government-support-2026`, `baby-cost-guide-first-year`, `elementary-school-ready-cost-2026`, `youth-savings-comparison-2026`, 비교 허브 `/compare/welfare/`
- **`아이맞이지원금`, `아동기본수당`은 프로젝트 전체에서 0건**. 2027 개편안을 다루는 페이지는 아직 없다.

### 1-3. 대표 페이지 결정: `birth-support-money`

| 기준 | `birth-support-total` | `birth-support-money` |
|---|---|---|
| 메인 키워드 정합 | “출산~2세 총지원금” | 기존 Title에 이미 “출산지원금” 포함 → **우위** |
| 출생순위 셋째 이상 | 없음 | 있음 → 아이맞이지원금 1,000/1,200/1,500만원 구조에 바로 대응 |
| 양육 방식 | 없음 | 가정양육/어린이집 입력 존재(현재 계산 미반영) → 가정보육 추가지원에 재사용 |
| 지역 입력 | 없음 | 있음 → 우대지역·아동수당 지역 차등에 재사용 |
| 데이터 구조 | JS 하드코딩 | `src/data/birthSupportMoney.ts` 정책 배열·배지·출처·확인일 |
| 설계 문서 | 없음 | `docs/design/202605/birth-support-money-design.md` 존재 |
| 내부 유입 | 32개 파일(헤더 메뉴 포함) | 6개 파일 |

내부 유입은 `birth-support-total`이 많지만 기능·키워드·데이터 구조가 `birth-support-money`에 압도적으로 유리하다. 유입은 2단계에서 링크 교체·301로 흡수한다(10번 참조). 두 페이지를 모두 2027로 갱신하면 같은 검색어로 경쟁하므로 하지 않는다.

## 5. 계산 로직 또는 데이터 구조

### 5-1. 계산식

```text
중앙정부 예상 지원금
= 출생 직후 지원 (첫만남이용권 또는 아이맞이지원금 기본액)
+ 월별 양육지원 (부모급여+아동수당 또는 아동기본수당 기본액)
+ 가정보육 추가지원 (개편안 0~23개월 가정보육 월 30만원)
+ 우대지역 추가지원 (개편안 아이맞이 +500만원, 아동기본수당 +10만원/월)

지자체 추가 지원금 = 데이터에서 금액이 확인된 지자체 항목만 (null은 0원 아님, '미반영')
전체 예상 지원금 = 중앙정부 예상 지원금 + 지자체 추가 지원금(확인된 경우만 표시)
```

- 우대지역 추가분을 기본액과 분리해 저장·표시한다(일반 vs 우대 차이 카드에 그대로 사용).
- 현행 체계 어린이집 이용 월: `부모급여 현금 = max(0, 부모급여 − 보육료)`. 보육료 바우처 자체는 양쪽 체계 모두 합계에 넣지 않는다(“현금성 지원 기준” 문장 표시). 근거: 개편안 발표에 보육료 변경 내용이 없어 같은 기준으로 비교하기 위함.
- 지자체 금액이 없는 지역에서 “전체 예상 지원금” KPI는 숨기고 “지자체 금액 미반영” 문장으로 대체한다. 불완전한 지역 데이터를 중앙정부 합계에 억지로 섞지 않는다.

### 5-2. 데이터 구조 (`src/data/birthSupportMoney.ts` 개편)

```ts
type DataBadge = '공식' | '참고' | '시뮬레이션' | '추정'; // '확인 필요' 배지 삭제(본문 텍스트로만)
type SystemId = 'current' | 'reform2027';

interface SupportItem {
  id: string;                 // 'firstMeeting' | 'parentBenefit' | 'childAllowance' | 'welcomeGrant' | 'childBasicAllowance' | 'homeCareAddon'
  system: SystemId;
  name: string;
  amountByOrder?: Record<1 | 2 | 3, number>;
  monthlyByAge?: { fromMonth: number; toMonth: number; amount: number }[];

```

`sources` 배열에 기관명·자료명·URL·발표일·확인일을 기록한다. 3-4의 미확정 항목은 `verified: false`로 두고 확정 시 해당 항목만 변경한다. `BSM_LOCAL_RULES`의 `badge: '확인 필요'`는 `참고` + `amount: null` + 본문 문장으로 바꾼다.

- #1: 200 + 100×12 + 50×12 + 10×24 = 2,240. 첫 1년 200 + 1,200 + 120 = 1,520.
- #5: 1,000 + 20×24 + 30×24 = 2,200. 첫 1년 1,000 + 240 + 360 = 1,600.
- #4-b: (1,500+500) + 30×24 + 30×24 = 3,440.
- #6-b: 200 + 110×12 + (50−47.5+10)×12 = 200 + 1,320 + 150 = 1,670.

**6월생 vs 7월생 해석(결과·FAQ·본문에서 활용)**: 수도권·첫째·가정보육 기준 첫 1년은 7월생이 80만원 많고(1,600 vs 1,520), 두 돌까지는 40만원 적다(2,200 vs 2,240). 차이는 장기로 갈수록 아동기본수당(20만 vs 10만원) 때문에 커진다. 장기 참고(만 13세 미만) 산식은 현행 200+1,800+10×156 = 3,560, 개편안 1,000+20×156+30×24 = 4,840으로 **차이 1,280만원이며 복지부 보도자료 예시와 일치**한다. 따라서 결과 문장은 “기간에 따라 유불리가 달라집니다”로 쓰고 “7월에 낳는 게 유리”라고 단정하지 않는다. 출산 시점 조정을 권하는 문구는 금지한다.

- `/tools/baby-government-support/`: 검색 의도는 다르지만 현재 데이터가 0~1세에 부모급여와 가정양육수당을 동시에 더하고(`BGS_TIMELINE.home` 0세 120만원), 아동수당을 “만 8세 미만·월 10만원 일괄”로 안내해 2026 공식 기준(9세 미만·지역 차등)과 다르다. **수정 전까지 링크 보류**, 별도 수정 작업으로 기록.
- 외부 CTA: 정부24 행복출산 원스톱, 복지로, 보건복지부 보도자료 원문. `target="_blank" rel="noopener noreferrer"`.

## 9. 리스크·주의사항

- **구현 전 재확인 필요**: 3-4의 10개 항목. 특히 #1 법적 확정, #2 경과규정, #5 우대지역 범위.
- 예산안 금액을 확정처럼 쓰지 않는다. 금지: “무조건 지급”, “확정 시행”, “2027년생 전체 적용”. 7월 1일 이후 출생아도 “적용 예정”으로 표기.
- 6월생 vs 7월생 비교가 출산 시점 조정 권유로 읽히지 않게 한다. Title·H1 주제로 쓰지 않는다.
- 현행 기존 데이터 오류 전파 금지: `birth-support-money`·`birth-support-total`·`baby-government-support` 모두 아동수당을 월 10만원 일괄로 계산 중이며, 2026년 4월 이후 지역 차등이 반영되지 않았다. 이번 개선에서 `birth-support-money`는 바로잡고, 나머지는 통합 또는 별도 수정.
- 현행 `DataBadge`에 `확인 필요` 배지가 있어 4종 배지 규칙 위반. 이번 개선에서 제거.
- 지자체 데이터 5개 지역 중 금액 확인은 강동구 1곳뿐. 중앙정부 합계에 섞지 않는다. 9번(중복 가능 여부) 확인 전에는 지자체 합산 결과에 추정 배지.
- 보육료 단가는 2026 프로젝트 기존 값(참고). 2027 보육료 고시 후 교체.
- 장기 참고(156개월) 구간은 제도 유지 가정이 커서 기본값으로 노출하지 않는다.
- URL state: 출생일·순위·지역 유형·우대 여부·양육 방식·기간만. 이름 등 개인정보 수집 없음. 입력값을 `textContent`로만 출력.
- 2026 데이터를 쓰는 다른 페이지(`single-parental-leave-total` 등)를 이번 작업에서 일괄 치환하지 않는다.
