## 1. 페이지 목적

"내 주식이 -20%, -30%, -50%인데 몇 % 올라야 원금이 복구될까?"에 즉시 답하고, 추가매수가 그 숫자를 얼마나 바꾸는지(그리고 무엇을 대가로 하는지) 보여준다.

## 2. 사용자 니즈

| 니즈 | 해결 |
|---|---|
| 손실률만 알고 있다 | "손실률만 입력" 간편 모드 |
| 매수가·현재가를 안다 | 가격 모드(기본) |
| 물타기하면 본전이 얼마나 가까워지나 | 추가매수 금액·가격 입력 → 평균단가·필요 상승률 비교 |
| 조금만 반등하면 어떻게 되나 | +5/+10/+20/+30% 반등 시 손익표 |
| 수수료까지 넣고 싶다 | 손익분기점 계산기로 이동 CTA |

## 3. 데이터 기준

외부 데이터 없음. 모든 결과는 사용자 입력 기반 계산이며 배지는 `시뮬레이션`으로 통일한다(사용자 입력 기반 가정값). 대표 손실률 표(-10%→+11.1% 등)는 수학적 항등식이므로 별도 배지 없이 "계산식" 라벨.

## 4. 입력값 / 섹션 구성

### 4-1. 입력값

| 입력 | id/data 속성 | 기본값 | 단위·제약 |
|---|---|---|---|
| 계산 모드 | `data-mode` | 가격 모드 | 가격 / 손실률만 |
| 매수가(평균단가) | `buyPrice` | 100,000 | 원, > 0 |
| 현재가 | `currentPrice` | 70,000 | 원, ≥ 0 (0이면 오류 안내) |
| 보유 수량 | `quantity` | 100 | 주, 정수 ≥ 1 |
| 손실률(간편 모드) | `lossRate` | 30 | %, 0 이상 100 미만 |
| 추가매수 금액 | `addAmount` | 0 | 원, ≥ 0 |
| 추가매수 가격 | `addPrice` | 현재가와 동일(자동) | 원, > 0, 사용자 수정 가능 |

빠른 프리셋 버튼: `-10%`, `-20%`, `-30%`, `-50%` (매수가 100,000 기준 현재가 자동 입력).

### 4-2. 섹션

1. Hero + 대표 예시 한 줄("-50%는 +100%가 필요합니다")
2. 입력 패널 (모드 탭, 프리셋)
3. 결과 요약 카드 4개: 현재 평가손실 / 손실률 / 본전까지 필요 상승률 / 손익분기 주가
4. 추가매수 비교 카드: 전·후 평균단가, 필요 상승률, 늘어난 투자원금, 남는 금액
5. 반등률별 손익표 (+5/+10/+20/+30%, 추가매수 전·후 2열)
6. 손실률 → 복구 필요 상승률 기준표 + 곡선 차트(-5%~-90%)
7. 주의 안내 (수수료·세금 미반영, 물타기 위험)
8. SEO 본문 + FAQ, 관련 계산기

## 5. 계산 로직 또는 데이터 구조

### 5-1. 산식

```text
투자원금 C0 = 매수가 × 수량
현재 평가금액 V0 = 현재가 × 수량
평가손익 = V0 − C0
손실률 L = 1 − 현재가 ÷ 매수가          (손실일 때 양수로 표기)
복구 필요 상승률 = C0 ÷ V0 − 1 = 매수가 ÷ 현재가 − 1 = L ÷ (1 − L)
손익분기 주가 = 매수가 (수수료·세금 미반영)

추가매수 수량 n = floor(추가매수 금액 ÷ 추가매수 가격)
실제 추가매수 금액 A = n × 추가매수 가격, 잔액 = 추가매수 금액 − A
추가매수 후 수량 Q1 = 수량 + n
추가매수 후 원금 C1 = C0 + A
평균단가 P1 = C1 ÷ Q1
추가매수 후 필요 상승률 = P1 ÷ 현재가 − 1

반등률 g 적용 시 손익 = 현재가 × (1 + g) × 보유수량 − 원금
반등 후 수익률 = (1 − L)(1 + g) − 1
```

### 5-2. 반올림·표시 기준 (확정)

- 내부 계산은 반올림 없이 원값 유지. 표시 단계에서만 반올림.
- 결과 카드 %: 소수 둘째 자리 반올림 (예: 42.86%). 기준표·FAQ 예시: 소수 첫째 자리 (예: 42.9%).
- 금액: 원 단위 반올림, 천 단위 콤마. 평균단가: 소수 둘째 자리까지 표시(예: 91,126.76원).
- 추가매수 수량은 정수 내림(소수 주 불가). 잔액을 함께 표시. 소수점 거래(해외주식 등)는 범위 외.
- 현재가 > 매수가(수익 상태): "이미 본전 위입니다" 안내 + 현재 수익률 표시, 필요 상승률 0%.

### 5-4. 경계값

| 입력 | 처리 |
|---|---|
| 현재가 0 또는 손실률 100% | 계산 불가 — "가격이 0이면 상승률로 복구할 수 없습니다" |
| 손실률 99% | +9,900% 표시(정상), 차트 y축은 -90%까지만 |
| 현재가 = 매수가 | 손실 0, 필요 상승률 0% |
| 추가매수 금액 < 추가매수 가격 | n = 0, "1주도 살 수 없는 금액" 안내, 추가매수 전 결과 유지 |
| 추가매수 가격 ≠ 현재가 | 필요 상승률은 **현재가 기준**으로 계산(평균단가 ÷ 현재가). 안내 문구 표기 |
| 음수·빈 값 | 직전 유효값 유지 + 필드 오류 메시지 |

## 6. 결과 화면 방향

- 핵심 카드 강조: "본전까지 +42.86% 필요"(큰 숫자) + 보조 "손실률 -30.00%" — 두 숫자의 비대칭을 시각적으로 대비.
- 추가매수 카드에 "필요 상승률 42.86% → 30.18%"와 함께 **"투자원금 10,000,000 → 12,940,000원(+29.4%)"**를 같은 크기로 노출해 위험 증가를 숨기지 않는다.
- 차트: 손실률(x) vs 필요 상승률(y) 곡선 + 사용자 위치 점. Chart.js, fallback 표.
- 모바일: 입력 → 요약 → 추가매수 → 반등표 순서. 표는 2열 카드로 전환.

## 7. SEO 본문 방향

### intro (4단락, 단락당 150자 이상)

1. **손실과 복구의 비대칭** — -50% 손실은 +50%가 아니라 +100% 상승이 필요한 이유를 원금 100만원 예시로 설명.
2. **계산 방법** — 매수가÷현재가−1 공식과 손실률 공식, 대표 손실률 표 읽는 법.
3. **추가매수(물타기)의 효과와 대가** — 평균단가가 낮아져 필요 상승률은 줄지만 투자금과 손실 가능 금액이 커진다는 점을 숫자로 설명.
4. **이 계산기의 범위** — 수수료·세금 미반영, 배당·분할 미반영, 미래 주가 예측이 아님. 비용 반영은 손익분기점 계산기 안내.

### FAQ (6개)

1. 주식이 -30%면 몇 % 올라야 본전인가요?
2. -50% 손실은 왜 100% 올라야 회복되나요?
3. 물타기를 하면 본전이 얼마나 빨리 오나요?
4. 추가매수 가격이 현재가와 다르면 어떻게 계산하나요?

6. 레버리지 ETF도 같은 공식으로 계산하면 되나요? (일별 재조정 때문에 지수 기준으로는 다름 → 레버리지 계산기)
