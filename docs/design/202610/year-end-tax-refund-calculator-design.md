# 연말정산 환급액 계산기 2026 개선 설계

> 작성일: 2026-10-07 · 작업: 기존 계산기 갱신 · 상태: 구현 및 개별 검증 완료, 전체 타입 검사 기존 오류 확인
> 입력 자료: 사용자가 첨부한 「연말정산 환급액 계산기 2026 개선」 기획서.
> 설계 본문은 작성 당시 기준이며, 최종 구현 결정과 검증 결과는 아래 구현 기록을 따른다. 배포는 수행하지 않았다.

## 2. 실제 구현 대조

2026-10-07 로컬 소스와 202605 기획·설계 문서를 읽어 확인했다. 아래는 과거 설계가 아닌 현재 코드 기준이다.

| 현재 위치·동작 | 문제·차이 | 개선 결정 |
|---|---|---|
| JS `calculate`: 0원 입력 시 `taxAmount × 0.92` 원천징수 추정 | 미입력과 실제 0원 혼동. 과거 설계에는 0.95로 기록 | 자동 추정 제거, `null`과 0 구분 |
| `calcPensionCredit`: 16.5%/13.2% | 지방소득세 포함 효과를 소득세 산식에서 차감 | 소득세 15%/12%, 지방 효과 별도 참고 |
| `renderKpi`: 연금저축 잔여 + IRP 잔여 합산 | 두 한도가 겹쳐 절세 여력 과대 표시 | 합산 잔여를 기준으로 표시, 두 계좌 대안은 독립 시나리오 |
| `readInputs`: 납입액 자체를 한도에 맞게 자름 | 실제 납입액·한도 초과분 사라짐 | 원입력 유지, 공제대상액만 제한 |
| 카드: 일반 신용·체크 두 그룹, 300/250/200만원 한도 | 특별 사용처와 2026 자녀 한도 미지원 | 배타적 사용처 그룹·2026 규칙 도입 |
| 자녀: 15/35/이후 30만원 | 첨부 기획의 최신 금액과 차이 | 최신 법문 검증 후 교체 |
| 월세: 7천만원·750만원, `isRenter`만 확인 | 현행 안내와 차이, 조건 불충분 | 8천만원·1천만원, 요건 확인 입력 |

| 초기화 순서: URL 복원 뒤 `applyPreset` | 복원값이 초기 프리셋으로 덮임 | 기본값 → URL 복원 → 1회 계산 |
| 입력 이벤트 `change` | 입력 즉시 갱신 아님 | 금액은 `input`, 선택은 `change` |
| 초기 DOM 5천만원, 실제 초기 프리셋 4천만원 | 첫 로드 값 불일치 | 단일 기본 상태 5천만원, 예시는 수동 선택 |
| OG는 홈 이미지, Chart.js 외부 CDN에 SRI 없음 | 전용 OG 없음·보안 정책 불일치 | 전용 OG 생성, 도넛 제거·진행률 사용 |

## 4. 데이터와 상태 설계

기존 `YETC_META`, `YETC_PRESETS`, `YETC_FAQ`, `YETC_RELATED_LINKS` export를 유지한다. 세율·공제 상수는 데이터 파일에서만 관리하고 JS의 하드코딩을 제거한다.

```ts
type Eligibility = 'unknown' | 'yes' | 'no';
interface YetcInput {
  grossSalary: number;
  withheldTax: number | null; // 올해 전체 예상 기납부 소득세, 지방소득세 제외
  withheldPeriod: 'annual' | 'ytd';
  dependents: number; // 본인 포함, 기존 dep 유지
  elderlyDependents: number;
  disabledDependents: number;
  children: number; // 자녀세액공제 요건을 충족한 자녀·손자녀
  cardLimitChildren: number; // 카드 한도 확대 법정 대상, 위 children과 별도
  creditCardAmount: number; // 아래 특별 사용처 금액 제외
  debitCashAmount: number;
  traditionalMarketAmount: number;
  publicTransportAmount: number;
  cultureSportsAmount: number;
  pensionInsuranceDeduction: number; // 실제 국민연금 등 공제대상 보험료
  socialInsuranceDeduction: number; // 건강·고용 등 실제 공제대상액
  housingSubscription: number;
  mortgageRepayment: number;
  housingEligible: Eligibility;
  medicalExpense: number; // 실손 보전 등 제외, 일반 의료비
  educationExpense: number; // 인별 한도·요건을 적용한 공제대상액 합계
  pensionSaving: number;
  irpAmount: number; // IRP·DC 본인 추가부담금, 회사부담금·이전금 제외
  insurance: number; // 일반 보장성, 장애인 전용 제외
  donationCreditInput: number; // 종류·한도 반영 후 소득세 세액공제액
  monthlyRent: number; // 연간 합계

  additionalSpend: number;

}
interface YetcScenario {
  additionalAmount: number;
  deductionIncrease: number;
  nominalCreditIncrease: number;
  incomeTaxDecrease: number; // 전체 재계산 전후 결정세액 차이
}
interface YetcResult {
  valid: boolean;
  taxBase: number;
  taxAmount: number;
  laborTaxCredit: number;
  finalTax: number;
  refund: number | null;
  refundScope: 'annual' | 'ytd' | 'unknown';

  cardRemainingToThreshold: number;
  cardDeduction: number;
```

금액은 모두 원 단위의 유한한 0 이상 정수로 정규화한다. 기본값은 총급여 50,000,000원, 본인 포함 1명, 기납부 `null`, 그 외 금액·인원 0, 조건 미확인, 추가 소비·납입 각 1,000,000원이다. `isRenter=false`이며 기본값만으로 월세를 공제하지 않는다.

## 5. 입력 UI와 기간 처리

| 탭 | 입력과 안내 |
|---|---|
| 기본 | 총급여, 기납부 소득세, 연간/현재 누적, 가족, 두 종류 자녀 수, 연금·사회보험 공제 |
| 올해 쓴 돈 | 일반 카드, 접힌 특별 사용처, 의료·교육·보험·기부 상세 |
| 절세 가능한 항목 | 연금저축, IRP, 월세와 조건, 주택자금 상세 |

라벨·도움말·결과는 모두 한국어로 표시한다. 카드 입력은「일반 신용카드」「일반 체크카드·현금영수증」「전통시장」「대중교통」「문화체육비」로 분리한다. 특별 사용처 금액을 일반 금액에 중복 입력하지 않도록 그룹 앞에 안내한다. 공제대상 외 지출은 제외한다.

총급여·공제 지출은 연간 예상 합계로 입력한다. 현재 누적액만 넣었다면 결과 역시 그 입력에 따른 시뮬레이션이며 자동으로 남은 달을 추정하지 않는다. 별도 추가 소비·납입은 현재 기준에서 한 번 더하는 가정이다. 연간 예상액에 이미 포함한 금액을 다시 넣지 않도록 안내한다.

기납부 입력 기본 안내: “올해 전체 예상 소득세를 입력하세요. 지방소득세는 제외합니다.” 현재 누적만 선택하면 “현재까지 낸 소득세 대비 차이”로 표시하며 연말 최종 환급으로 표현하지 않는다. 미래 원천징수 자동 추정은 하지 않는다.

범위: 금액 0~10,000,000,000원, 인원 0~20명, 본인 포함 가족 1~20명. 음수·소수 인원·NaN·Infinity는 오류 표시하고 해당 계산을 중단한다. 큰 납입액을 공제한도로 강제 수정하지 않는다. 총급여 0은 안내 후 결과와 시나리오를 비운다. 가족 간 인원 관계를 확인하고 경로우대·장애인은 서로 중복 가능하게 한다.

## 6. 계산 계약

### 6.1 공통 파이프라인

근로소득공제 → 근로소득금액 → 인적·연금보험료·사회보험·주택·카드 소득공제 → 0 이상 과세표준 → 누진 산출세액 → 근로소득세액공제 및 기타 공제 → 0 이상 결정세액 → 기납부 비교.

근로소득공제·8개 세율 구간은 기존 구조를 재사용하되 데이터로 이동하고 현행 법령과 대조한다. 근로소득세액공제의 산출 방식·총급여별 한도와 표준세액공제 13만원 대안은 반드시 검증 후 구현한다. 표준세액공제와 특별공제의 적용 관계를 반영해 유효한 대안 중 결정세액이 낮은 쪽을 선택한다. 서로 양립 불가한 공제를 단순 합산하지 않는다.

원 미만 내부 계산은 유지하고, 과세표준·세액의 법정 절사 시점은 검증한 규칙으로 통일한다. 화면 포맷 반올림이 다음 계산 입력에 영향을 주면 안 된다.

### 6.2 환급

`refund = withheldTax === null ? null : withheldTax - finalTax`.

- 미입력: 예상 결정세액과 “환급액을 보려면 기납부 소득세를 입력하세요”.
- 실제 0원: 유효 입력, 결정세액만큼 추가납부 방향 표시.
- 양수 / 0 / 음수: 예상 환급 / 차액 없음 / 예상 추가납부.
- 결과와 시나리오 모두 `시뮬레이션` 배지. 공식 배지는 세율·법정 한도에만 사용.

### 6.3 카드

`threshold = grossSalary × 0.25`, `remaining = max(0, threshold - eligibleSpendTotal)`.

현재 일반 카드 계산은 신용부터 문턱을 충당한다. 특별 사용처를 추가할 때에는 법정 최저사용금액 차감식과 추가한도를 확인한 별도 함수로 확장한다. 결제수단별 원금에 일괄 공제율을 곱한 뒤 단순 총합으로 계산하지 않는다. 문화체육비의 급여요건·대상시설·적용기간·제외금액도 규칙에 넣는다. 자녀 한도 수는 자녀세액공제 대상 수와 자동 공유하지 않는다.

`calcCardDeduction`은 문턱, 차감 전 공제액, 문턱 차감액, 기본한도, 추가공제액, 최종액을 반환한다. 기본한도 초과분과 특별 사용처 공제액 사이의 법정 추가공제 제한을 반영하여 특별 사용처를 이중 공제하지 않는다.

추가 신용카드와 체크카드 비교는 각각 독립적으로 원래 상태에 동일 금액을 더해 전체 파이프라인을 재계산한다. `추가 소득공제 = 변경 공제 - 현재 공제`, `예상 소득세 감소 = 현재 결정세액 - 변경 결정세액`. 한계세율 곱셈은 설명용으로도 실제 결과를 대체하지 않는다.

### 6.4 연금

```text
eligibleSaving = min(pensionSaving, 6,000,000)
eligibleCombined = min(eligibleSaving + irpAmount, 9,000,000)
combinedRemaining = max(0, 9,000,000 - eligibleCombined)
savingRemaining = min(max(0, 6,000,000 - eligibleSaving), combinedRemaining)
nominalCredit = eligibleCombined × (총급여 ≤ 55,000,000 ? 0.15 : 0.12)
```

첨부의 단순 잔여 산식을 보완한다. 연금저축 800만원·IRP 0이면 공제대상 600만원이고 IRP 추가 공제대상 여력은 300만원이다. 한도 초과 연금저축 200만원을 합산 공제대상으로 세지 않는다.

추가 납입은 계좌 선택 + 50/100/200/300만원 빠른 입력 + 직접 입력. 한도 밖 납입액도 입력을 유지하고 추가 공제대상액만 제한한다. 명목 세액공제 증가와 실제 결정세액 감소를 별도 표시한다. 결정세액이 이미 0이면 명목 공제 증가가 있어도 예상 세금 감소는 0이다. 두 계좌 시나리오는 합산 가능한 효과처럼 표시하지 않는다.

지방소득세는 소득세 감소의 10%를 단순 참고로 표시하는 경우에만 별도 `추정` 행을 제공한다. 공식 소득세 공제율·환급과 합치지 않는다.

### 6.5 월세·가족·기타

월세: 무주택과 기타 조건이 확인되고 총급여가 8천만원 이하일 때 `min(연간 월세, 1천만원) × 17% 또는 15%`. 미확인은 적용을 보류하고 조건 확인 안내. 조건에는 세대주·세대원 공제 관계, 종합소득금액 제외 기준, 임차주택 규모 또는 기준시가, 계약자·전입·지급증빙을 포함한다. 정확한 법정 요건은 출처와 함께 확인 목록으로 제공한다.

자녀: 검증 후 0/25/55/95만원(0~3명), 이후 1명당 40만원. 기본공제·연령·중복 적용 관계를 안내한다. 카드 한도 확대 대상의 연령·관계는 별도 검증한다.

의료비는 일반 의료비의 급여 3% 문턱·일반 한도를 적용한다. 본인·고령자·장애인·난임 등 특례는 직접 자동 분류하지 않고 미반영 안내. 교육비는 대상자별 한도를 적용한 공제대상액 합계 입력으로 명확화하여 전체에 일률 900만원 제한을 제거한다. 기부금은 산정 완료 소득세 세액공제액 직접 입력으로 변경한다. 기존 `don` 지출액을 새 세액공제액으로 자동 해석하지 않는다.

주택청약·전세대출은 기존 입력 유지 + 요건 확인. 청약의 납입대상 한도와 산출공제 한도를 구분하고 합산 한도를 적용한다. 표준세액공제 선택과 각 특별공제의 관계를 검증한다.

순수 계산 함수는 대표·경계·포화·세율구간·표준공제 대안을 자동 검증한다. 규칙의 단순 복제 테스트보다 수기 기대값·공식 사례·시나리오 전후 차이를 검증한다. UI는 320/480/640/820px·데스크톱, 키보드 탭 이동, 실시간 결과, URL 복원, 공제 상세 읽기, 광고가 입력값을 수집하지 않는지 확인한다.
