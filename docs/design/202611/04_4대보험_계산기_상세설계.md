## 1. 갱신 방식과 호환성

기존 `/tools/four-insurance-calculator/`를 유지한다. 페이지를 새 2027 경로로 복제하지 않는다. 2026 계산도 선택 가능하게 보존하고, 2027 계산 가능 범위와 가정 여부를 화면 상단에서 안내한다.

수정 대상은 기존 `src/data/fourInsuranceCalculator.ts`, `src/pages/tools/four-insurance-calculator.astro`, `public/scripts/four-insurance-calculator.js`, 기존 SCSS다. `employeeTaxInsuranceRates2026.ts`는 요율표 리포트도 참조하므로 2027 값으로 직접 덮어쓰지 않는다. 새 기간별 규칙과 2번 공용 함수를 명시적으로 연결한다.

현재의 `rates.<key> || fallback`을 가용성 판정으로 사용하지 않는다. 요율 0·미확정·필드 누락을 구분한다. 기존 `calcNationalPension`, `calcHealthInsurance`, `calcLongTermCare`, `calcEmploymentInsurance`를 함수 경계별로 교체하고 숫자 기본값에 숨어 있는 2026 규칙을 제거한다. `calcEstimatedIncomeTax`는 공식 간이세액표가 아니므로 공식 표 계산이라는 문구를 붙이지 않는다. 실제 코드의 URL query 상태·복사 동작도 기본 페이지 공유 정책과의 호환을 별도로 검토한다.

기존 기능 중 보존 대상: 월 급여·비과세·가족 입력, 국민연금·고용보험 적용 선택, 회사 부담 참고, 간이 세금·실수령액. 단, 검증되지 않은 계산을 그대로 확정 결과로 유지한다는 뜻은 아니다. 기존 로직을 기능별 어댑터로 격리하고 지원 상태를 명시한다.

제안 기능 플래그:

| 플래그 | 활성 조건 | 비활성 대안 |
|---|---|---|
| insurance_2027_verified_total | 모든 적용 보험의 기준·단수·요율 검증 | 확정 항목 소계 |
| insurance_2027_scenario_total | 명시적 가정 규칙·사용자 선택 | 가정 합계 없음 |
| payroll_tax_official | 적용 간이세액표·입력요건 검증 | 세금 직접 입력 또는 제외 |
| payroll_tax_legacy_preview | 기존 추정식의 범위 검토 | 기존 추정 결과 숨김 |
| employer_reference | 지원하는 회사 항목의 규칙 검증 | 회사 부담 표시 안 함 |

## 3. 입력·비교 모드

기본 모드는 ‘같은 산정 기준에서 2026·2027 비교’다. 소득 변화 포함 비교는 고급 모드다.

```ts
type InsuranceKind = 'pension' | 'health' | 'long_term_care' | 'employment';
type BasisMode = 'simple_estimate' | 'explicit_bases';
type PayrollPeriodInput = {
  month: string;
  grossPayWon: bigint;
  nonTaxablePayWon: bigint;
  basisMode: BasisMode;
  explicitBases?: {
    pensionReportedBasisWon?: bigint;
    healthMonthlyRemunerationWon?: bigint;
    employmentRemunerationWon?: bigint;
  }; // applies인 보험의 기준만 필수, 종속 조건은 런타임 검증
  applicability: Record<InsuranceKind, 'applies' | 'not_applicable' | 'unknown'>;
};
type FourInsuranceInput = {
  comparisonMode: 'same_basis' | 'changed_pay';
  before: PayrollPeriodInput;
  after: PayrollPeriodInput;
  assumptions: {
    employmentScenarioRuleId: string | null;
  };
  taxes: { before: TaxInput; after: TaxInput };
};
```

간편 입력은 급여-비과세를 공통 출발 추정치로 사용한다. 해당 값이 보험별 공식 보수 정의와 같다는 보장은 없으므로 `basisKind='estimated_from_pay'`를 결과에 남긴다. 각 보험 함수는 자기 규정에 따라 기준을 처리한다.

고급 입력의 reported pension basis는 국민연금 모듈의 신고 기준 검증을 따른다. 건강보험·고용보험에 서로 다른 보수 값을 입력할 수 있다. applies인 보험의 기준 필드는 필수이며 not_applicable인 보험의 값은 계산에 사용하지 않는다. 근로자 자격 판정을 생년월일·국적 추측으로 자동화하지 않는다.

같은 기준 비교에서는 한 묶음의 보험별 입력값을 공유한다. 기간별 상·하한 규정 차이로 산정 후 기준이 달라질 수 있으면 ‘같은 입력 소득 기준’이라고 표시하고 실제 적용 기준도 표에 보인다. ‘급여 변화 없음’과 ‘산정 결과 동일’을 혼동하지 않는다.

## 4. 입력 검증과 종속 조건

| 조건 | 처리 |
|---|---|
| grossPay 빈칸 | 제출 불가 |
| grossPay ≤0 | 일반 월급 계산 범위 안내 |
| nonTaxable > grossPay | 필드 오류 |
| 간편 기준 급여-비과세=0 | 보험별 하한 적용 전에 신고·자격 확인 필요 안내 |
| 건강보험 미적용+장기요양 적용 | 모순 입력 오류 |
| 건강보험 적용 여부 unknown | 건강·요양 결과 둘 다 미확인 |
| 보험 unknown | 해당 항목을 0으로 간주하지 않음 |
| 고급 필드 누락 | 해당 필드 오류, 간편값으로 자동 대체 안 함 |
| 변경 급여 비교의 한 연도 누락 | 전후 비교 불가 |
| 세금 가족 수 <1 | 본인 포함 입력 정책에 맞춰 오류 |

건강보험을 미적용으로 바꾸면 장기요양도 not_applicable로 변경하고 이유를 알린다. 다시 적용으로 바꿀 때 일반 기본은 요양 적용으로 되돌리되, 이전 특례 선택을 조용히 승계하지 않는다.

## 5. 결과 타입과 합계 정책

```ts
type InsuranceItemResult =
  | {
      status: 'calculated';
      kind: InsuranceKind;
      employeeWon: bigint;
      employerWon: bigint | null;
      appliedBasisWon: bigint;
      basisKind: 'reported' | 'estimated_from_pay';
      provenance: Provenance;
    }
  | { status: 'not_applicable'; kind: InsuranceKind; reason: string }
  | { status: 'unavailable'; kind: InsuranceKind; issue: Issue };
type InsuranceAggregate = {
  items: InsuranceItemResult[];
  verifiedSubtotalWon: bigint;
  includedKinds: InsuranceKind[];
  missingKinds: InsuranceKind[];
  completeTotalWon: bigint | null;
  scenarioTotalWon: bigint | null;
};
```

not_applicable는 사용자가 해당 보험 미적용을 확인한 상태이며 합계에서 금액 0의 의미를 갖는다. unavailable은 적용하지만 기준이 미확인이거나 자격이 unknown인 상태다. 두 상태를 같은 숫자로 렌더링하지 않는다.

`completeTotalWon`은 모든 적용 항목이 calculated이거나 명시적 미적용일 때만 존재한다. 검증 소계는 계산 성공한 항목만 합산하되 그 목록을 함께 보인다. 가정 총계는 별도 규칙에서 계산하며 검증 소계·completeTotal을 덮어쓰지 않는다.

전후 차액:

- 양쪽 모두 complete이면 전체 차이를 반환한다.
- 하나라도 incomplete이면 공통 계산 가능 항목의 교집합만 비교한다.
- 공통 소계 차액은 ‘비교 가능한 항목 소계 차이’로 표시하고 항목 목록을 밝힌다.
- 한쪽의 국민연금+건강보험+요양과 다른 쪽의 그 항목+고용보험을 빼서 차이를 내지 않는다.
- 가정 비교는 동일 가정 정책의 전후 결과끼리만 비교한다.

## 6. 계산 파이프라인

```text
raw input
 → 정규화·필드 검증
 → 기간별 rule bundle 조회
 → 각 보험 basis 산정
 → 국민연금 / 건강보험 / 고용보험 계산
 → 건강보험 결과를 이용해 장기요양 계산
 → 항목별 가용성 집계
 → 같은 범위 전후 비교
 → 선택 세금 처리
 → 결과 ViewModel
```

국민연금은 `calculatePensionMonthly`를 호출한다. 별도 5% 상수를 4대보험 파일에 작성하지 않는다. 건강보험은 보수월액·상하한·분담·단수 규칙을 갖는 독립 함수다. 장기요양은 건강보험과 의존 관계가 있어 건강보험 계산 실패 시 독립적인 가짜 값을 만들지 않는다.

고용보험은 일반 근로자 실업급여 부담과 사업주 추가 부담을 구분한다. 요율 변경 외 산정 정의 변경이 있으면 새 rule version을 등록한다. 2026 기준 정의를 2027에 무조건 재사용하지 않는다.

핵심 함수 계약:

```ts
validatePayrollPeriod(raw): ValidationResult<PayrollPeriodInput>
resolveInsuranceRuleBundle(month, manifest): RuleLookup<InsuranceRuleBundle>
calculateHealthInsurance(input, rules): CalcResponse<HealthResult>
calculateLongTermCare(healthResult, rules): CalcResponse<LongTermCareResult>
calculateEmploymentInsurance(input, rules): CalcResponse<EmploymentResult>
aggregateInsuranceItems(items): InsuranceAggregate
compareInsuranceScopes(before, after): InsuranceComparison
calculatePayrollCash(period, insurance, taxInput, taxRules): CalcResponse<PayrollCashResult>
calculateFourInsuranceComparison(input, manifest): CalcResponse<FourInsuranceComparison>
```

최상위 비교 함수는 일부 항목 unavailable 때문에 전체를 즉시 실패시키지 않는다. 입력 자체가 invalid이면 실패하고, 항목별 결과가 생성되면 불완전 소계·전후 비교 범위를 포함한 결과를 반환한다. `FourInsuranceComparison`은 before/after aggregate, 공통 항목 차이, 선택 세금 결과, 가정 여부, provenance를 포함한다.

## 7. 건강보험·장기요양 규칙 타입

```ts
type HealthRule = RuleMeta & {
  totalRate: SerializedRatio;
  employeeShare: SerializedRatio;
  employerShare: SerializedRatio;
  lowerPremiumWon: IntegerString | null;
  upperPremiumWon: IntegerString | null;
  assessmentSteps: SerializedCalculationStep[];
};
type LongTermCareRule = RuleMeta & {
  basis: 'health_premium';
  linkedRatio: SerializedRatio;
  displayedIncomeEquivalentRate: SerializedRatio | null;
  healthBaseStage: string;
  assessmentSteps: SerializedCalculationStep[];
};
```

보험마다 상한을 소득 기준으로 정하는지 보험료 기준으로 정하는지 공식 규정대로 타입을 선택한다. 건강보험료 상한을 국민연금 소득 상한 필드에 억지로 넣지 않는다.

healthBaseStage는 장기요양이 건강보험 총액/근로자분/단수 처리 전후 중 어떤 값을 참조하는지 검증된 단계 ID다. 건강보험·요양 분담과 절사 순서를 단순 가정하지 않는다. 연결 비율은 소득 대비 요율을 건강보험료에 직접 곱하는 오류를 방지하도록 별도 필드로 둔다.

기획서의 2027 의결·발표 수치는 [요율 상태 표](../../plan/202611/04_4대보험_계산기_2027_갱신_기획.md)에서 확인한다. 본 설계는 법령 최종 시행 검증을 완료했다는 선언이 아니다.

## 8. 세금·실수령액 분리

```ts
type TaxInput =
  | { mode: 'excluded' }
  | { mode: 'manual'; incomeTaxWon: bigint; localTaxWon: bigint }
  | { mode: 'official_table'; familyCountIncludingSelf: number;
      eligibleChildCount: number; withholdingOption: '80' | '100' | '120' }
  | { mode: 'legacy_preview' };
type PayrollCashResult = {
  grossPayWon: bigint;
  insuranceTotalWon: bigint | null;
  incomeTaxWon: bigint | null;
  localTaxWon: bigint | null;
  takeHomeWon: bigint | null;
  label: 'after_insurance' | 'estimated_take_home' | 'preview' | 'unavailable';
};
```

공식 간이세액표 옵션은 현재 적용 규정·가족·자녀·원천징수 선택의 유효성을 확인한 후 활성화한다. 자녀 나이를 기존 UI의 20세 이하로 고정하지 않는다. 공식 표 변환 데이터에는 원문 파일·행 구간·검토 기록을 보존한다.

excluded: 완전 보험료 합계가 있으면 gross-insurance를 ‘보험료 공제 후 금액’으로 표시한다. 세후 실수령액이라고 하지 않는다.

manual: 사용자가 급여명세서의 국세·지방세를 각각 입력한다. 보험료 완전 합계가 있을 때만 두 금액을 차감한 추정 수령액을 낸다. 급여 이외 공제는 미포함임을 표시한다.

official_table: 시행일별 표를 조회해 월 소득세와 지방세를 계산한다. 표 밖의 고액 구간은 공인 공식 수식이 검증된 경우만 지원한다. nearest 구간이나 임의 보간으로 처리하지 않는다.

legacy_preview: 기존 로직을 검토해 보조 기능으로 허용한 경우만 쓴다. 화면·분석 outcome을 확정 계산과 분리한다. 가정 보험료 총계와 결합한 경우 모든 결과가 가정임을 표시한다.

비과세는 산정기준을 조정할 뿐 실제 지급 급여에서 한 번 더 빼지 않는다. 불완전 보험료 소계만으로 실수령액을 산출하지 않는다. 공제액이 급여보다 커 음수 수령액이 나오면 0으로 덮지 않고 입력·예외 정산 범위 확인을 안내한다.

## 9. 회사 부담 영역

근로자 결과와 분리된 참고 패널이다. 국민연금 회사분, 건강보험·요양 회사분, 고용보험 지원 범위만 표시한다. 산재는 업종별 규칙 검증과 적용 업종 선택 없이는 계산하지 않는다.

회사 전체 부담을 지원하려면 별도 EmployerInput이 필요하다: 업종 코드, 사업장 규모, 관련 사업 구분, 산재 요율과 적용기간. 초기 기본안에서는 이 필드를 추가하지 않고 ‘지원 항목의 회사 부담 참고액’이라고 명명한다. 표시 토글은 근로자 합계·실수령액을 바꾸지 않는다.

| FI_SCENARIO_NOT_OPTED_IN | 가정 총계 미선택 | 가정 결과 계산·표시 안 함 |

| FI_TAX_TABLE_UNSUPPORTED | 표·구간 미지원 | 세금 제외/직접 입력 대안 |
| FI_TAKE_HOME_INCOMPLETE | 보험료·세금 불완전 | 실수령액 미표시 |

모드·기준월·적용 선택·비과세·가족 조건 변경 시 result revision 무효화. 회사 부담 표시와 근거 펼치기는 계산 입력이 아니므로 기존 결과를 유지한다. 프리셋은 금액뿐 아니라 어떤 기본 가정을 적용하는지 표시한다.
