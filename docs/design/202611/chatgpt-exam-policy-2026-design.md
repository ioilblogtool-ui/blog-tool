## 3. 데이터 구조와 판정 규칙

| 데이터 | 필드와 표시 규칙 |
|---|---|
| 메타 | `slug`, `title`, `description`, `ogImage`, `asOf`, `datePublished`, `dateModified`. 확인일과 공개일은 따로 기록한다. |
| 공식 출처 | `id`, `publisher`, `title`, `url`, `publishedAt`, `version`, `checkedAt`, `scope`. 발표일이나 버전 미상은 생략하고 확인일을 표시한다. |
| 평가 비교 행 | `id`, `evaluationType`, `scope`, `allowedMaterials`, `internetAccess`, `aiStatus`, `aiScope`, `disclosure`, `contact`, `nextStep`, `sourceIds`. 자료, 인터넷, AI 허용 여부는 서로 독립적이다. |
| 예시 | `scenario`, `allowedUse`, `disclosureExample`, `sourceIds`. 가상 평가임을 표시하고 실제 강의 정책처럼 보이지 않게 한다. |
| FAQ·관련 링크 | `question`, `answer`, `sourceIds`; `href`, `label`. 기획서의 FAQ 6문항을 기반으로 본문과 동일한 판단 기준을 사용한다. |

| 화면 상태 | 적용 조건 | 다음 행동 |
|---|---|---|
| 금지 | 적용 규정이 해당 도구·기능 또는 해당 외부 도움을 금지함 | AI 기능을 사용하지 않고 허용 물품·도구 목록 확인 |
| 허용 | 적용 공지에서 도구·기능을 명시적으로 허용하고 해당 작업에 별도 AI 조건을 두지 않음 | 허용된 기능과 시험 운영 규칙 범위 안에서 사용 |
| 조건부 허용 | 허용 작업 단계, 기능 제한, 공개·제출 요건이 존재함 | 지정 범위와 기록·표기 조건 확인 |
| 규정 미확인 | 해당 평가의 공개 근거가 부족하거나 여러 안내의 적용 관계가 명확하지 않음 | 적용 지침과 평가 공지를 확인하고 담당자에게 도구·기능·단계를 명시해 문의 |

근거 배지는 기관 원문에 `공식`, 가상 적용 예시와 표기 예문에 `참고`를 사용한다. 원문이 지침이나 권고인 경우 그 성격을 표시한다. 대학·강의·전형·학년도 범위를 맨 앞에 두고, 같은 문서에 여러 사용 조건이 있으면 확인 가능한 작업 단위로 나눈다.

## 4. 화면 구성과 초기 표시안

| 순서·앵커 | 표시 내용 |
|---|---|
| 1 · `#overview` | 제목, 기준일, “오픈북 시험이라면 허용 자료·인터넷·생성형 AI를 각각 확인하세요.” 요약 |
| 2 · `#check` | 강의계획서 → 시험·과제 공지 → 담당자 확인. 확인 질문에 도구, 기능, 사용 단계, 표기·제출 조건을 포함 |
| 3 · `#comparison` | 평가 유형, 적용 범위, AI 상태, 확인할 공지·담당자, 제약·다음 행동. 출처를 해당 행에서 바로 열 수 있게 연결 |
| 4 · `#disclosure` | 허용된 과제의 AI 사용 기록 예시. 교정·번역·요약·초안·코드 생성은 공지에 기재된 기능 단위로 확인 |
| 5 · `#sources` | 기관·문서명·버전·확인일과 적용 범위 |
| 6 · `#faq` | `SeoContent`에 소개 4단락, FAQ 6개, 허브·AI 학습·AI 코딩 도구 링크 표시 |

| 평가 | 초기 비교표에 넣을 내용 |
|---|---|
| 대학 감독 시험 | 연세대 지침의 감독 시험 원칙을 해당 기관 사례로 소개. 다른 강의·대학의 상태는 별도 공지 확인 |
| 대학 온라인 시험 | 고려대 원격교육센터 지침을 사전 공지 근거로 연결. 개별 시험의 AI 상태는 규정 미확인으로 두고 공지로 안내 |
| 오픈북 시험 | 교재 허용 여부를 자료 항목으로 표시. 인터넷과 AI 상태는 적용 공지에서 각각 확인 |
| 과제·보고서 | 부산대 지침의 도구명·목적·범위 공개 예시. AI 사용 허용이 선행되고 공개 조건이 붙는 경우에 조건부 허용 표시 |
| 논문 | 소속기관 연구윤리, 학위논문 제출 지침, 투고처 저자 안내 확인. 공개 원문이 없는 개별 사례에는 규정 미확인 표시 |
| 코딩 시험 | 기본 자동완성과 생성형 코드 제안·채팅을 구분해 운영기관에 확인. 공개 원문 확보 전에는 개별 허용 여부를 단정하지 않음 |
| 국가자격시험 | 큐넷의 공단 시행 국가기술자격 전자통신기기 제한 사례. 전문자격은 종목 공고 확인 |
| 수능 | 2027학년도 교육부 공지의 전자기기 한정 규칙 안내. 세부 처분·사례는 허브 연결 |

가상 과제 표기 예문은 “ChatGPT를 문장 표현 점검에 사용했습니다. 최종 문장과 인용은 원문과 대조해 작성했습니다.”를 사용한다. 이용자가 실제 사용한 도구, 범위와 검증 과정에 맞추게 하고, 프롬프트·출력 제출은 해당 공지에서 요구하는 경우를 설명한다.

표에는 `caption`과 행·열 헤더를 두고 모바일 가로 스크롤을 표 영역에 한정한다. 스크롤 영역에 이름과 키보드 접근을 제공한다. 상태는 텍스트로 표시하고 초점 표시가 가려지지 않게 한다.

## 6. SEO와 구현 완료 기준

- [ ] H1, 메타 설명, canonical, OG, 목록 링크와 사이트맵이 정규 URL을 사용한다.
- [ ] Article JSON-LD의 제목과 실제 게시·갱신일이 화면과 일치한다. FAQ 답변은 기획 기준 6개를 화면에 표시한다.
- [ ] 교재만 허용된 오픈북, AI 명시 허용, 교정만 조건부 허용, 공지 불명확의 네 상황에서 비교표와 FAQ의 상태가 일치한다.
- [ ] 공식 사례의 적용 범위와 문서 직접 링크가 표시되며, 가상 예시에 참고 표시가 붙는다.
- [ ] 홈·리포트 목록·기존 허브에서 신규 URL을 찾을 수 있고 신규 페이지에서 기존 허브로 이동할 수 있다.
- [ ] 모바일·태블릿·데스크톱에서 페이지 전체의 가로 넘침, 목차 이동, 비교표 키보드 접근과 FAQ 펼침을 확인한다.
- [ ] 구현 후 빌드와 카테고리 매핑 검사를 통과하고 생성 HTML을 확인한다.
