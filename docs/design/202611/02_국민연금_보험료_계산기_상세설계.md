## 1. 기능 결정

제안 경로: `/tools/national-pension-contribution-calculator/`.

실제 파일 패턴: `src/data/nationalPensionContributionCalculator.ts`, `src/pages/tools/national-pension-contribution-calculator.astro`, `public/scripts/national-pension-contribution-calculator.js`, `src/styles/scss/pages/_national-pension-contribution-calculator.scss`. DOM 없는 공용 함수는 `public/scripts/national-pension-contribution-core.js` 같은 ES module로 분리해 4번에서 import한다. 기존 저장소에는 순수 함수를 export하고 Node 검증에서 import하는 선례가 있으므로 새 실행 프레임워크는 필요 없다.

기존 `employeeTaxInsuranceRates2026.ts`는 2026 요율표의 단일 출처로 보존한다. 새 기간별 데이터를 추가하거나 명시적 어댑터를 만들고, 기존 페이지의 2026 뜻을 바꾸지 않는다. tools.ts·홈 topicBySlug·tools/index 분류·app.scss·sitemap·OG 등록을 확인한다. 계산기 쉘과 컴포넌트는 기존 것을 사용한다.

## 3. 도메인 타입

```ts
type Subscriber = 'employee' | 'regional';
type PensionInput =
  | {
      mode: 'rate_only';
      subscriber: Subscriber;
      fixedBasisWon: bigint;
      fromYear: 2026;
      toYear: 2027;
    }
  | {
      mode: 'monthly_estimate';
      subscriber: Subscriber;
      from: PensionMonthlyInput;
      to: PensionMonthlyInput;
    };
type PensionMonthlyInput = {
  month: string;
  basisInput:
    | { kind: 'reported_basis'; amountWon: bigint }
    | { kind: 'income_estimate'; amountWon: bigint };
};
type PensionBurden = {
  basisWon: bigint;
  subscriberWon: bigint;
  employerWon: bigint | null;
  totalWon: bigint;
  calculationKind: 'official_estimate';
  adjustments: PensionAdjustment[];
};
type PensionAdjustment = {
  kind: 'income_rounding' | 'lower_bound' | 'upper_bound' | 'premium_rounding';
  beforeWon: bigint;
  afterWon: bigint;
  ruleId: string;
};
type RationalWon = { numerator: bigint; denominator: bigint };
type RateOnlyBurden = {
  basisWon: bigint;
  subscriberWon: RationalWon;
  employerWon: RationalWon | null;
  totalWon: RationalWon;
  calculationKind: 'rate_only';
};
type PensionComparison<TBurden, TAmount> = {
  mode: PensionInput['mode'];
  before: TBurden;
  after: TBurden;
  subscriberDeltaWon: TAmount;
  employerDeltaWon: TAmount | null;
  monthlyDeltaAnnualizedWon: TAmount;
  annualizationMonths: 12;
};
type PensionRateComparison = PensionComparison<RateOnlyBurden, RationalWon>;
type PensionMonthlyComparison = PensionComparison<PensionBurden, bigint>;
```

‘지역가입자 회사 부담 없음’은 null이다. 본인 부담과 전체 부담은 지역 모드에서 같다. 지원금 반영 전이므로 지원으로 줄어든 개인 납부액과 같다고 설명하지 않는다.

## 4. 규칙 분리와 의존성

요율표, 소득 산정, 상·하한, 단수·분담 규칙을 독립 레코드로 둔다. 하나의 연도 객체 안에 아직 모르는 미래 상한을 채워 넣지 않는다.

```ts
type PensionRateRule = RuleMeta & {
  year: number;
  total: SerializedRatio;
  employee: SerializedRatio;
  employer: SerializedRatio;
};
type PensionBasisRule = RuleMeta & {
  lowerWon: IntegerString;
  upperWon: IntegerString;
  incomeRounding: SerializedRounding;
};
type PensionAssessmentRule = RuleMeta & {
  steps: AssessmentStep[];
};
```

`AssessmentStep[]`는 적용 순서를 명시한다. 소득 절사 → 상하한 적용 → 전체 보험료 → 부담 배분 → 단수 처리 중 실제 공식 규정의 순서를 검증해 채운다. 본인·회사 금액을 독립 반올림해 전체 금액과 어긋나게 만드는 임의 알고리즘을 확정하지 않는다.

4대보험에 제공할 공용 함수는 `calculatePensionMonthly`다. 국민연금 페이지 전용 비교 함수가 4대보험 화면 상태나 DOM을 참조해서는 안 된다.

## 5. 함수 인터페이스

```ts
parsePensionForm(raw): ValidationResult<PensionInput>
resolvePensionRate(year, manifest): RuleLookup<PensionRateRule>
resolvePensionBasis(month, manifest): RuleLookup<PensionBasisRule>
calculatePensionRateOnly(input, rateRules): CalcResponse<PensionRateComparison>
calculatePensionMonthly(input, ruleBundle): CalcResponse<PensionBurden>
comparePensionMonthly(input, manifest): CalcResponse<PensionMonthlyComparison>
buildPensionRatePath(fixedBasis, subscriber, years, rules): CalcResponse<RatePath>

```

이름은 제안이며 저장소 구조에 맞춰 바꿔도 계약은 유지한다. `rate_only` 함수는 basis rule을 요구하지 않는다. `monthly_estimate`는 적용월의 모든 필수 규칙을 요구한다.

## 6. 계산 알고리즘

### 6.1 요율 비교

1. fixedBasisWon > 0 및 입력 정책 상한 이내인지 확인한다.
2. 2026·2027 요율 규칙의 출처·검토·법적 상태를 확인한다.
3. 동일 B에 각 요율을 정확한 유리수로 적용한다.
4. 이 모드는 공식 보험료 단수 처리까지 포함하지 않는 ‘요율 적용액’이다. 계산값은 유리수로 보유하고 최종 표시에서 원 단위 반올림한다. 화면에 ‘단수 처리·상하한을 제외한 요율 비교’라고 표시한다.
5. 차액은 반올림 전 요율 적용액 차이로 계산한 뒤 표시 반올림한다. 월·연 환산도 같은 원시 차액에서 파생한다.

위 원칙에 따라 rate_only는 `RateOnlyBurden`과 `RationalWon`을 사용하고 ViewModel에서 표시 금액으로 변환한다. 공식 월 추정은 `PensionBurden`과 원 단위 정수를 사용한다. 두 비교 결과를 제네릭과 별칭으로 분리해 혼용을 막는다.

표시 정합성: 원 미만이 있는 요율 비교는 상세에 반올림 안내를 노출한다. 결과 차이가 표시된 전후 값의 차이와 1원 다르면 임의로 고치지 않고 ‘원 미만 반올림으로 차이가 있을 수 있음’을 표시한다. 공식 추정 모드는 해당 규정에서 확정한 원 단위 결과끼리 차감한다.

### 6.2 기간별 월 보험료 추정

1. 각 기준월의 유효한 요율·basis·assessment rule을 찾는다.
2. reported_basis면 신고 기준소득월액의 단위·범위를 검증한다. 범위를 벗어나면 자동 수정하지 않고 입력 확인을 요청한다.
3. income_estimate면 검증된 산정 규칙을 따라 절사·상하한을 적용하고 adjustments에 기록한다.
4. 공식 assessment steps로 본인·회사·전체를 계산한다.
5. from/to 양쪽 성공 때만 비교 결과를 만든다. 한쪽 unavailable이면 완전 비교를 제공하지 않는다.

reported_basis를 소득 입력처럼 다시 절사·상한 처리하면 사용자가 준 확정 기준액을 바꿀 수 있다. 두 입력 종류를 분리한 이유다.

### 6.3 12개월 환산과 경로

월 차액×12는 ‘월 차액의 12개월 환산’이다. 실제 연간 추정 기능은 월별 rule을 12번 찾아 합산하는 별도 기능이며 이번 범위에 없다.

2033 경로는 같은 B·같은 가입 유형·지원 없음·미래 상하한 미반영이다. 각 연도 요율의 출처가 검증됐을 때만 생성한다. 해당 경로로 미래 실제 고지액을 단정하지 않는다.

공식 근거와 향후 경로는 [기획서 요율표·출처](../../plan/202611/02_국민연금_보험료_계산기_2027_기획.md)에 연결한다. 본 문서는 새로운 공단 조회를 수행한 데이터 검증 완료 보고서가 아니다. 상·하한·절사 설정은 값이 확보될 때까지 draft로 둔다.

지원금 문의는 기본 계산의 실패 사유가 아니라 범위 경고다. 지원금을 반영한 결과를 요구한 경우에만 unsupported로 전환한다.

## 9. ViewModel과 증감 표현

핵심 필드: afterMonthlyLabel, afterSubscriberAmount, monthlyDeltaText, annualizedDeltaText, basisCaption, modeCaption, adjustmentNotes, details, provenance.

월 차액 >0이면 ‘월 X원 증가’, <0이면 ‘월 X원 감소’, 0이면 ‘월 부담 차이 없음’. 계산되지 않은 차액에는 ‘차이 없음’을 쓰지 않는다.

연도 표 하단: 직장은 본인+회사=전체 검증, 지역은 본인=전체 검증. 요율 비교는 원 미만 표시 정책에 따른 화면 차이를 허용하되 내부 유리수 합계는 정확해야 한다. 회사 항목 토글은 계산이 아니라 표시만 바꾼다.

## 10. 검증 데이터와 수용 기준

요율 비교에서 다음은 원 미만이 없는 독립 수기 사례다.

|---|---|---:|---:|---:|---:|---:|
| T2-01 | 직장 | 2,000,000 | 95,000 | 100,000 | 5,000 | 60,000 |
| T2-02 | 직장 | 3,000,000 | 142,500 | 150,000 | 7,500 | 90,000 |
| T2-03 | 직장 | 5,000,000 | 237,500 | 250,000 | 12,500 | 150,000 |

추가 사례: B=3,000,001의 유리수·반올림 표시, reported_basis 단위 오류, 상하한 전후, 기간 끝일·다음 시작일, 규칙 기간 중복, 가입 유형 전환 후 결과 무효화, 월급 추정과 신고액 직접 입력의 차이.

공식 추정 golden fixture에는 period, inputKind, input, normalizedBasis, employee, employer, total, roundingRuleIds, sourceIds를 모두 기록한다. 공식 사례가 없으면 수기 계산을 독립 검토하고 근거 조문을 붙인다.

## 11. 개발 순서와 완료 조건

1. 입력 파서·유리수 계산·요율 조회.

3. 화면·상태·결과·2033 경로.
4. 기준소득월액·단수·부담 배분 검증 후 monthly 함수.
5. 4대보험에서 공용 monthly 함수 호출·결과 일치 확인.
