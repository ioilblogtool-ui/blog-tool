|---|---|---|---|

| 2 | 국민연금 보험료 계산기 신규 | 기존 국민연금 계산기는 수령액 관련, 별도 보험료 증가액 전용 페이지는 이번 조사에서 발견하지 못함 | 신규 유지, 기존 2026 보험 데이터와 연계 |

## 2. 기존 설계에서 고칠 결정

### R-01. 연말정산 URL 중복 방지

근거 파일:

- `src/pages/reports/2026-year-end-tax-saving-guide.astro`
- `src/data/yearEndTaxSavingGuide2026.ts`
- `src/styles/scss/pages/_2026-year-end-tax-saving-guide.scss`
- `src/data/reports.ts`, 홈·리포트 허브 메타, sitemap의 기존 등록.

새 `/reports/year-end-tax-checklist-2026/`는 생성하지 않는다. 기존 URL의 본문과 메타를 ‘2026 귀속·2027 정산·연말 체크리스트’ 의도에 맞춘다. 신규 URL이나 리디렉션을 만들 필요가 없다. 기존에 참조된 앵커가 있으면 호환 여부를 확인한다.

### R-02. 환급 계산기 확장 중복 제거

현재 계산기는 `src/data/yearEndTaxRefundCalculator.ts`와 `public/scripts/year-end-tax-refund-calculator.js`로 구성돼 있다. `createCalculator`, `calcCardDeduction`, `calcPensionCredit`, `compareScenario`, 입력 검증·공유 상태 함수가 이미 존재한다.

확인한 기능: 카드 25% 문턱, 같은 추가 지출의 신용/체크 비교, 연금 추가 납입 비교, 명목 공제와 실제 소득세 감소 분리, 기납부 소득세 미입력 시 환급 null. 기존 페이지는 지방소득세를 합산하지 않는다고 안내한다.

따라서 STEP01에서 카드·연금계좌 엔진을 재구현하지 않는다. 기존 계산 결과의 국세 범위에 맞춰 리포트를 설명하고 기존 CTA를 재사용한다. 수식 변경이 필요한 오류가 발견되면 별도 범위로 기록한다.

### R-03. 반도체 주 비교 범위 수정

`src/utils/samsungMicronEarnings2026.ts`의 `validateReportData`는 메인 snapshot `recordIds`에 연결실적만 허용한다. DS·메모리는 `segmentRecordIds`에 분리해 표시하는 구조다.

기존 설계의 ‘삼성 DS를 메인 3사 표에 직접 대체’는 현재 검증 계약과 충돌한다. 구현 확정안은 **전사 연결실적 3사 비교 유지 + 삼성 DS 별도 사업부 표 보강**이다. DS를 주 비교로 승격하는 별도 모드는 이후 필요할 때 모델·검증·표를 함께 설계한다. 이를 위해 기존 검증을 느슨하게 만들지 않는다.

### R-04. 공통 아키텍처의 실제 파일 매핑

기존 저장소는 `src/data/*.ts` → `.astro` → JSON 주입 → `public/scripts/*.js` 흐름이다. 일반적인 domain/presentation/대규모 rule registry 폴더를 한 번에 신설하지 않는다. 순수 함수·버전·검증이라는 설계 원칙만 실제 파일 패턴에 맞춰 구현한다.

금융 계산의 새 정밀 모듈은 해당 새 기능에서 먼저 사용한다. 기존 number 기반 계산기 전체를 이번 작업으로 bigint로 변환하지 않는다. 기존 결과가 회귀하는 변경은 별도 검토한다.

## 4. 개인정보·공유 정책의 실제 차이

환급 계산기는 이미 `recordSessions={false}`, `loadAds={false}`, `before-tracking`의 `no-referrer`를 사용한다. 하지만 `syncUrl`이 입력을 `#yetc=` fragment에 기록하고 복사 버튼은 입력 포함 링크를 복사한다.

기존 설계의 ‘모든 입력은 URL에 저장되지 않음’은 현재 코드의 사실이 아니다. fragment는 서버 요청 query와 다르지만 주소 기록·복사 링크·페이지 스크립트에는 노출될 수 있다.

STEP01에서는 계산기 공유 동작을 바꾸지 않는다. 리포트 체크 상태는 메모리만 사용하고 URL·localStorage·분석에 넣지 않으며 BaseLayout의 recordSessions=false로 세션 재생 자동 수집도 끈다. 계산기 CTA는 깨끗한 canonical 경로만 연결한다. 기존 공유 정책 변경은 별도 후속 이슈로 관리한다. 2~4번 새 기능/갱신에서는 기본 무저장·페이지 링크만 공유를 명시적 기능 요구로 적용하고 호환 정책을 따로 검토한다.

## 5. 사이트 기준과 문서 충돌 처리

| 항목 | 문서의 오래된 설명 | 실제 코드 기준 |
|---|---|---|
| Astro 버전 | ARCHITECTURE는 4.x | package.json은 ^5.5.5. 실제 설치 버전은 lockfile/실행환경 확인 |
| CSS 변수 | ARCHITECTURE는 :root 토큰 없음·사용 금지 | `_tokens.scss`에 CSS custom properties가 실제 존재. CONTENT_GUIDE·UI_ARCHITECTURE도 토큰 사용 방향 |
| FAQ props | 일부 가이드는 q/a | `SeoContent.astro`는 question/answer |
| FAQ 스키마 | 일부 가이드는 자동 생성이라고 설명 | SeoContent에는 FAQPage 생성 없음. 각 페이지의 jsonLd에서 구성 여부 확인 |
| 입력 갱신 | 가이드마다 제출 버튼/실시간 혼재 | 기존 환급 계산기는 실시간. STEP01에서 제출 버튼 흐름으로 바꾸지 않음 |
| 빌드 | 일부 문구는 CI 빌드만 언급 | AGENTS·품질·배포 기준의 로컬 build 요구까지 구현 완료 체크에 포함 |

이번 검토에서는 저장소의 공통 가이드 파일을 수정하지 않는다. 구현 문서에 실제 확인된 패턴을 명시하고, 오래된 예시를 복사해 새 코드와 충돌시키지 않도록 한다. 토큰 값은 문서 표의 색상을 베끼지 말고 현재 `_tokens.scss`에서 참조한다.

## 6. 등록·검증 파일 확정

기존 리포트 개편인 STEP01은 기존 등록을 유지한다. 신규 항목을 중복 추가하지 않는다. 제목·description·수정일·관련 링크가 바뀌는 등록 위치만 갱신한다.

- `src/data/reports.ts`
- `src/pages/index.astro`의 reportMetaBySlug
- `src/pages/reports/index.astro`의 reportMetaBySlug
- `src/styles/app.scss`의 기존 import 유지
- `public/sitemap.xml`의 기존 loc 유지, lastmod 정책 확인
- `public/og/` 이미지 경로·생성 방식 확인 후 메타 일치

신규 2·3번은 tools.ts + 홈 topicBySlug + tools/index 분류·설명 + SCSS import + sitemap + OG를 모두 확인한다.

기존 검증 스크립트:

- `node scripts/check-year-end-tax-refund-calculator.mjs`
- `node scripts/check-samsung-micron-earnings.mjs`
- `node scripts/check-category-mapping.mjs`
- 실제 구현 후 `npm run check:all`, `npm run build`, 해당 route 생성·브라우저 확인.

## 7. 이번 검토의 실행 결과와 한계

- 환급 계산기 기존 검증 스크립트: 23개 사례 통과 확인.
- 반도체 검증: 실적 산식·예외·범위·3사 확장·스냅샷 보존·SEO 검증 통과.
- 카테고리 검증: 기존 스크립트가 검사하는 매핑에서 누락 없음으로 통과. 전체 기능 검증을 뜻하지 않는다.
- 전체 Astro check/build 및 브라우저 시각 검수: 이번 문서 검토에서 실행하지 않음.
- Git HEAD 조회는 `693fd746885e03fbf441b0c07ff1eaa7b13beb9f`, branch 조회는 main을 반환했다. 다만 status는 소유권/작업트리 관련 오류로 정상 확인하지 못했다. 작업트리가 깨끗하다거나 로컬 파일이 HEAD와 같다고 보증하지 않는다.
- 저장소 소스·설정·Git 전역 설정은 변경하지 않았다. 구현 시에는 변경 상태와 소유권/작업트리 문제부터 확인한다.

검증 스크립트 통과는 내장 사례에 대한 결과이며 공식 세법 전수 대조·실제 UI 동작·운영 배포 확인을 의미하지 않는다.

## 8. 첫 구현 확정 범위

1. 기존 연말정산 가이드를 2026 귀속·2027 정산으로 명확히 개편.
2. 월세·의료비·환급 표현·근거 없는 순위를 공식 근거와 계산 범위에 맞춰 정리.
3. 6개 공제 준비 체크리스트 추가. 해당 여부와 준비 상태를 구분, 저장 기능 없음.
4. 기존 카드·연금계좌 설명을 실제 계산기의 지원 기능에 맞춰 연결.
5. FAQ·출처·메타·구조화 데이터·기존 허브 정보를 동기화.
6. 기존 계산기 엔진·공유 정책은 이번 단계에서 유지하고 회귀 검증.

새 앱·새 환급 엔진·공통 상태 프레임워크·새 체크리스트 URL은 만들지 않는다. 아직 사이트 소스를 수정한 상태가 아니라, 이 변경 범위를 기준으로 구현을 시작할 준비가 된 상태다.
