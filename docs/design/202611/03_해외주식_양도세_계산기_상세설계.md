## 1. 기능 경계

초기 버전은 일반 세율이 적용되는 국외주식 과세대상 개인의 원화 기준 실현손익 계산이다. 거래내역 자동 분석·신고 대행·매도 권유·특례 자산·혼합 국내 과세주식의 세율 배분은 포함하지 않는다.

경로는 인벤토리에서 동일 목적 페이지 존재 여부를 확인한 뒤 정한다. 신규일 때 제안값은 `/tools/overseas-stock-capital-gains-tax-calculator/`다.

실제 매핑: `src/data/overseasStockCapitalGainsTaxCalculator.ts`, 대응 Astro 페이지, `public/scripts/overseas-stock-capital-gains-tax-calculator.js`, 대응 SCSS partial. 기존 부동산 capital-gains의 누진·장기보유·주택 비과세 엔진을 재사용하지 않는다. 환차익 계산기는 세금을 계산하지 않으므로 신규 계산기의 원화 손익 설명과 관련 링크로 연결한다. 등록은 tools.ts·홈·tools 허브·app.scss·sitemap·OG를 포함한다. 입력·결과 쉘과 URL 없는 페이지 링크 복사는 기존 컴포넌트에 맞춰 최소 구현한다.

## 3. 자격 모델과 지원 판정

```ts
type OverseasEligibility = {
  asset: 'overseas_listed_stock_or_etf' | 'domestic_listed_etf' | 'other';
  residency: 'eligible' | 'ineligible' | 'unknown';
  standardRate: 'yes' | 'no' | 'unknown';
  mixedDomesticTaxableStock: 'no' | 'yes' | 'unknown';
  specialTaxAdjustment: 'no' | 'yes' | 'unknown';
};
```

`eligible`는 단순 국적이 아니라 공인 안내에 따른 과세대상 거주 요건을 확인했다는 사용자 선택이다. UI에는 요건 요약과 공식 링크를 제공한다. 해당 요약은 [기획서 적용대상·출처](../../plan/202611/03_해외주식_양도소득세_계산기_2026_기획.md)의 배포 전 검증 대상이다.

지원 판정: 해외 상장 일반 자산, 거주 요건 eligible, standardRate yes, 국내 혼합 no, 특례 no가 모두 충족돼야 기본 엔진을 실행한다. unknown을 ‘아니오’로 취급하지 않는다. 일반 세율을 자동 판정하기 위해 종목명을 수집하지 않는다.

## 4. 입력 타입

```ts
type CostInput =
  | { kind: 'already_included' }
  | { kind: 'separate_eligible_cost'; amountWon: bigint };
type ProfitLossRow = {
  id: string; // 로컬 UI 식별자
  realizedGainWon: bigint;
  realizedLossAbsWon: bigint;
  cost: CostInput;
};
type OverseasInput = {
  taxYear: 2026;
  eligibility: OverseasEligibility;
  mode: 'aggregate' | 'accounts';
  rows: ProfitLossRow[];
};
type OverseasScenario = {
  gainWon: bigint;
  lossAbsWon: bigint;
  cost: CostInput;
};
```

손실은 입력에서 양수 절대값이다. 음수 입력을 다시 차감해 이익이 늘어나는 오류를 막는다. 계좌 이름은 받지 않고 화면상 ‘계좌 1, 2…’로 표시한다.

기본 합계 모드는 행 1개다. 이익·손실 필드가 모두 빈칸이면 미입력 오류, 한쪽에 정상값이 있고 다른 쪽이 빈칸이면 비어 있는 쪽을 0으로 처리한다. 사용자가 0을 명시한 경우는 실제 0으로 구분해 계산한다. 전부 빈 계좌 행은 무시하되 활성 행이 1개 이상 필요하다.

추가 계좌는 최대 20행으로 제안한다. 이는 법정 계좌 수 제한이 아니라 입력 UI 정책이다. 공제를 받기 위해 계좌별 계산을 하는 구조가 아니라 전체 순손익을 합산하는 구조다.

## 5. 합계/계좌 모드 전환 정책

합계→계좌: 현재 합계 이익·손실·비용을 ‘계좌 1’로 옮긴다. 기존 합계는 별도 합산하지 않는다. 비용 상태도 함께 이전한다.

계좌→합계: 활성 행의 이익·손실·별도 비용을 각각 합산해 1행으로 바꾼다. 계좌별 내역은 합계로 통합된다는 문구를 표시한다. 합산된 별도 비용이 0이면 already_included, 0보다 크면 separate_eligible_cost로 둔다.

모드 변경은 동일 경제적 값의 합계를 보존해야 한다. 결과는 재제출 전 숨긴다. 계좌를 삭제하면 바로 입력 합계에서 제외하되 실수 방지를 위해 실행 취소 1회 UI를 선택 제공한다. 삭제 확인 대화상자를 반복 요구하지 않는다.

## 6. 규칙 모델

```ts
type OverseasTaxRule = RuleMeta & {
  taxYear: 2026;
  deductionWon: IntegerString;
  nationalRate: SerializedRatio;
  localRate: SerializedRatio;
  localTaxBasis: 'taxable_income' | 'national_calculated_tax';
  nationalRounding: SerializedRounding;
  localRounding: SerializedRounding;
  intermediateRoundingSteps: SerializedCalculationStep[];
};
```

localRate는 localTaxBasis에 맞춰 설정한다. 과세표준 기준 2%와 국세 기준 10%를 같은 설정에 혼용하지 않는다. 현재 일반 교육 예시는 합계 22% 상당이지만 실제 엔진은 검증된 신고 계산 단계·절사를 구현한다.

해외주식 기본공제·국세 일반 세율의 근거는 기획서 공식 국세청 자료에 연결한다. 지방세 및 단수 규칙은 출처를 보강해 `cross_checked` 이후에만 확정 엔진을 활성화한다. 누락 상태에서는 22% 근사 계산을 확정 세액처럼 대신 제공하지 않는다.

## 7. 계산 계약

```ts
type OverseasTaxBreakdown = {
  gainWon: bigint;
  lossAbsWon: bigint;
  separateCostWon: bigint;
  netGainWon: bigint;
  nominalDeductionWon: bigint;
  deductionAppliedWon: bigint;
  deductionRemainingWon: bigint;
  taxableBaseWon: bigint;
  nationalTaxWon: bigint;
  localTaxWon: bigint;
  totalTaxWon: bigint;
};
type OverseasComparison = {
  before: OverseasTaxBreakdown;
  after: OverseasTaxBreakdown;
  taxDeltaWon: bigint; // after - before
};
```

함수:

```ts
validateOverseasEligibility(input): EligibilityResult
normalizeProfitLossRows(rows): ValidationResult<ProfitLossTotals>
calculateOverseasTax(totals, rule): CalcResponse<OverseasTaxBreakdown>
compareOverseasScenario(totals, scenario, rule): CalcResponse<OverseasComparison>
```

순서:

1. 자격·연도·필드 범위를 검증한다.
2. G=각 행 이익 합, L=각 행 손실 절대값 합, F=별도 적격 비용 합.
3. N=G-L-F.
4. appliedDeduction=min(max(N,0), D).
5. taxableBase=max(N-D,0).
6. remainingDeduction=D-appliedDeduction. 순손실일 때도 D보다 크게 만들지 않는다.
7. 검증된 국세·지방세 규칙을 적용하고 합산한다.
8. 시나리오는 G·L·F에 추가 값만 더해 같은 함수를 다시 호출한다.
9. taxDelta=after.total-before.total. 별도 매매손익과 합치지 않는다.

총 손실 때문에 과세표준 0이 돼도 음수 세금·자동 환급·다음 해 손실 이월액을 생성하지 않는다. 기본공제보다 이익을 더 실현할 여지가 생긴 경우도 ‘공제 잔여액’과 동일 필드로 표현하지 않는다.

## 8. 원화·수수료·실현손익 처리

원화 입력만 제공한다. 증권사 양도소득 계산 자료에서 확인한 손익을 권장한다. 해외 자산 평가 화면의 수익률·달러 평가손익·현재 환율을 자동 결합하지 않는다.

수수료 포함 여부 기본값은 ‘입력 손익에 이미 반영’이다. 별도 선택 때 ‘이미 반영된 비용은 다시 넣지 마세요’와 비용 종류 확인 경로를 표시한다. 세법상 적격성 검증 없이 거래 관련 모든 비용을 자동 공제하지 않는다.

실현손익 기준일과 귀속연도 설명은 본문에서 제공한다. 시장별 결제주기·연말 휴장까지 계산하는 일정 엔진은 만들지 않는다. 사용자의 거래 완료 여부를 임의 판단하지 않는다.

## 9. 상태 전이와 결과 정합성

기준 계산 성공 후에만 시나리오 패널을 활성화한다. 시나리오 필드 수정은 시나리오 결과만 무효화한다. 기준 입력·자격·연도가 바뀌면 기준 결과와 시나리오 결과를 모두 무효화한다.

| 동작 | 기준 결과 | 시나리오 입력 | 시나리오 결과 |
|---|---|---|---|
| 기준 입력 변경 | 숨김 | 보존 가능 | 숨김 |
| 자격 미지원 변경 | 삭제 | 삭제 | 삭제 |
| 기준 계산 재실행 | 갱신 | 보존 | 재제출 필요 |
| 시나리오 삭제 | 유지 | 0/빈값으로 초기화 | 삭제 |
| 전체 초기화 | 삭제 | 삭제 | 삭제 |

시나리오 비교 버튼은 ‘기준 결과 revision과 현재 기준 입력 revision이 같음’을 조건으로 활성화한다. 이전 기준 세금과 새 시나리오를 비교하지 않는다.

## 10. 결과 ViewModel

핵심 카드: 예상 총 세액 / 공제 후 과세표준 / 일반 모드 공제 잔여액. 상세: 이익, 손실, 비용, 순손익, 명목 공제, 실제 적용 공제, 국세, 지방세.

세금 감소는 taxDelta<0일 때 절대값으로 ‘예상 세금 X원 감소’. 증가는 양수로 ‘증가’. 같으면 ‘현재 조건에서 차이 없음’. 미지원·미확정이면 숫자 카드 대신 안내를 보인다.

시나리오 비교 바로 아래에 ‘세금 감소액은 손실 금액을 보전하는 투자수익이 아닙니다’를 넣는다. 매도·재매수 추천 버튼은 제공하지 않는다. 분석 이벤트에는 손실 여부·규모도 보내지 않는다.

## 13. SEO·측정·완료 조건

본문·적용대상·방법론·FAQ·출처는 초기 HTML에 포함하고 개인 금액은 브라우저 상태에만 둔다. canonical에 입력값을 붙이지 않는다. 급여 연말정산과 해외주식 양도세는 별도 절차로 안내하며 연결한다.

이벤트는 시작·성공·시나리오 사용·공식 안내 클릭이다. 자산명·손익·계좌 수는 전송하지 않는다. 완료 조건은 대상 판정, 계산·비교, 상태 무효화, 단수 처리 검증, 대표 사례, 모바일·키보드, 로그의 입력값 미전송 확인까지 포함한다.
